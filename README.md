# ระบบขอซื้อเครื่องมือช่าง — Meiwa Tool Request

Google Sheets + Apps Script • ใช้บนมือถือ • ช่างไม่ต้องมีอีเมลและไม่ต้องล็อกอิน

ช่างส่งคำขอได้หลายรายการในใบเดียว แนบรูปเครื่องมือตัวเดิม/ลิงก์สินค้า และระบุราคาที่เห็นที่ร้าน
(เช่น Global House) เพื่อให้จัดซื้อใช้เทียบราคา — จัดซื้อเสนอตัวเลือกพร้อมรูป สเปค ผู้ขาย ราคา
VAT ค่าส่ง วันที่ได้ของ และเงื่อนไขชำระเงิน — ช่างกดยืนยัน/ปฏิเสธ **แยกทีละรายการ** แล้วเลือกว่า
จะให้จัดซื้อสั่งซื้อ หรือช่างไปซื้อเองที่ร้าน จบด้วยขั้น **อนุมัติของฝ่ายจัดซื้อ** ซึ่งแยกจากการยืนยันสเปคของช่าง

> **หลักสำคัญ:** ช่างยืนยันสเปค ≠ อนุมัติให้สั่งซื้อ
> ระบบเก็บสองสถานะแยกกัน (`tech_status` และ `purchase_status`) การสั่งซื้อจริงเกิดขึ้น
> ก็ต่อเมื่อฝ่ายจัดซื้อกด "อนุมัติสั่งซื้อ" เท่านั้น

## 1. ภาพรวมการทำงาน

| ขั้น | ใคร | เกิดอะไรขึ้น | สถานะ |
|---|---|---|---|
| 1 | ช่าง | ส่งคำขอหลายรายการ + รูป + ลิงก์ + ราคาที่ร้าน | รอเสนอราคา |
| 2 | จัดซื้อ | เพิ่มตัวเลือก 1 หรือหลายตัวต่อ 1 รายการ | รอช่างยืนยัน |
| 3 | ช่าง | ยืนยัน / ไม่ตรงสเปค (ต้องบอกเหตุผล) / ขอให้แก้ไข — **ทีละรายการ** | รอเลือกวิธีซื้อ |
| 4 | ช่าง | เลือก "จัดซื้อสั่งซื้อ" หรือ "ซื้อเองที่ร้าน" (ต้องใส่ราคาประเมิน + ยืนยันว่าขอใบกำกับภาษีได้) | **รออนุมัติ** |
| 5 | จัดซื้อ | อนุมัติ / ไม่อนุมัติ → สั่งซื้อ → รับของ หรือ ช่างซื้อเองแล้วอัปโหลดใบเสร็จ | เสร็จสิ้น |

ทุกการกดบันทึก **ชื่อผู้ตัดสินใจ + วันเวลา** ลงชีต `History` และดูย้อนหลังได้ทั้งฝั่งช่างและจัดซื้อ

**3 หน้าจอ**

| หน้า | ลิงก์ | ใคร | ล็อกอิน |
|---|---|---|---|
| ฟอร์มขอซื้อ | `<WEBAPP_URL>` | ช่าง | ไม่ต้อง |
| ติดตาม/ยืนยัน | `<WEBAPP_URL>?p=r&t=<token>` | ช่าง (ลิงก์ส่งทาง LINE) | ไม่ต้อง |
| แดชบอร์ดจัดซื้อ | `<WEBAPP_URL>?p=dash` | จัดซื้อ | PIN |
| ค้นหาคำขอของฉัน | `<WEBAPP_URL>?p=find` | ช่าง (กรณีลิงก์หายใน LINE) | ไม่ต้อง |

## 2. โครงสร้างข้อมูล (Google Sheet structure)

ระบบสร้าง 7 ชีตให้อัตโนมัติตอนติดตั้ง **หัวตารางแถวที่ 1 ห้ามแก้ชื่อหรือสลับลำดับ**
(โค้ดอ่าน/เขียนตามชื่อคอลัมน์) เพิ่มคอลัมน์ต่อท้ายเองได้ถ้าต้องการจดบันทึกเพิ่ม

| ชีตในระบบ | เทียบกับชื่อที่ใช้ทั่วไป | เก็บอะไร |
|---|---|---|
| `Requests` | Requests | 1 แถว = 1 ใบขอซื้อ |
| `Items` | Items | 1 แถว = **1 เครื่องมือ** (1 ใบมีได้หลายแถว) |
| `Options` | PurchaseOptions | 1 แถว = 1 ตัวเลือกที่จัดซื้อเสนอ (1 เครื่องมือมีได้หลายตัวเลือก) |
| `History` | History / Decisions | บันทึกทุกการกดแบบต่อท้ายอย่างเดียว **ห้ามลบ** |
| `Technicians` | Users | รายชื่อช่างสำหรับ dropdown |
| `Config` | Settings | PIN, อีเมลจัดซื้อ, VAT, ข้อมูลใบกำกับภาษี |
| `Notifications` | — | คิวข้อความ LINE/อีเมล พร้อมสถานะส่งแล้ว/ยังไม่ส่ง |

**เลขที่เอกสาร** — `REQ-2026-0001` (เลขรันเริ่มใหม่ทุกปี) และรายการย่อยคือ
`REQ-2026-0001-01`, `-02`, … ส่วนตัวเลือกของจัดซื้อคือ `REQ-2026-0001-01-O1`, `-O2`, …
ความสัมพันธ์: `Requests 1 : N Items 1 : N Options`

### คอลัมน์ในแต่ละชีต

**`Requests` (10)**
`req_id` `token` `created_at` `requester_name` `site` `contact` `required_date` `note` `status` `updated_at`
`token` = รหัสสุ่ม 16 ตัวในลิงก์ที่ส่งให้ช่างทาง LINE

**`Items` (33)** — หัวใจของระบบ แบ่งเป็น 4 กลุ่ม

| กลุ่ม | คอลัมน์ |
|---|---|
| สิ่งที่ช่างขอ | `item_id` `req_id` `seq` `tool_name` `qty` `unit` `required_date` `intended_use` `spec_pref` `brand_pref` `item_note` `benchmark_price` `benchmark_store` `ref_links` `ref_photos` |
| ช่างยืนยันสเปค | `tech_status` `tech_note` `decided_by` `decided_at` `chosen_option_id` `pur_note` |
| วิธีซื้อ | `fulfil_mode` (`SUPPLIER`/`LOCAL`) `local_est_price` `local_store` `tax_invoice_ok` `receipt_url` `receipt_at` |
| จัดซื้ออนุมัติ | `purchase_status` `approved_by` `approved_at` `approval_note` `po_ref` `updated_at` |

> `tech_status` และ `purchase_status` **แยกกันคนละคอลัมน์โดยเจตนา**
> ช่างเขียนได้แค่ฝั่งซ้าย จัดซื้อเท่านั้นที่เปลี่ยน `purchase_status` เป็น `APPROVED` ได้

**`Options` (22)**
`option_id` `item_id` `created_at` `created_by` `brand` `model` `spec` `supplier` `product_link`
`photo_url` `unit_price` `vat_rate` `vat_amount` `shipping` `subtotal` `total_cost`
`availability` `delivery_date` `payment_terms` `note` `is_recommended` `status`
ช่อง `subtotal` `vat_amount` `total_cost` ระบบคำนวณให้ ไม่ต้องกรอก
(`subtotal = unit_price × qty`, `vat = (subtotal + shipping) × vat_rate%`)

**`History` (8)**
`ts` `req_id` `item_id` `option_id` `actor` `role` `action` `detail`
ตรงกับที่ต้องการ: *วันเวลา | เลขที่ | รายการ | ผู้ทำ | การกระทำ | รายละเอียด*
(สถานะเก่า/ใหม่ดูได้จากชื่อ `action` เช่น `CONFIRM_SPEC`, `APPROVE_PURCHASE`, `STATUS_ORDERED`)

**`Technicians` (5)** `name` `nickname` `site` `line_id` `active` — `active` = `Y`/`N`
**`Config` (3)** `key` `value` `note`
**`Notifications` (9)** `ts` `channel` `to` `ref` `subject` `message` `link` `status` `error`

### สถานะ

| ในชีต | ความหมาย | ใครเปลี่ยน |
|---|---|---|
| `tech_status` | `WAITING_OPTION` → `WAITING_TECH` → `CONFIRMED` / `CHANGE_REQUESTED` / `REJECTED` | ช่าง |
| `purchase_status` | `NEW` → `WAITING_TECH` → `PENDING_APPROVAL` → `APPROVED` → `ORDERED` → `RECEIVED` → `CLOSED` (หรือ `REJECTED` / `CANCELLED`) | จัดซื้อ |

ระบบรวมสองคอลัมน์นี้เป็น **ขั้นตอนเดียวที่แสดงบนหน้าจอ (stage)** ซึ่งก็คือแท็บบนแดชบอร์ด

| stage | แท็บที่เห็น | ต้องทำอะไร |
|---|---|---|
| `NEED_OPTION` | รอเสนอราคา | จัดซื้อหาของและเสนอตัวเลือก |
| `CHANGE_REQ` | ช่างขอแก้ไข | ช่างตีกลับ — จัดซื้อเสนอตัวเลือกใหม่ |
| `TECH_SPEC` | รอช่างยืนยัน | ช่างตรวจสเปค |
| `TECH_MODE` | รอเลือกวิธีซื้อ | ช่างเลือกจัดซื้อสั่ง/ซื้อเอง |
| `APPROVAL` | รออนุมัติ | **จัดซื้ออนุมัติ** (ยังไม่ใช่ตอนที่ช่างยืนยัน) |
| `TO_ORDER` | รอสั่งซื้อ | จัดซื้อสั่งของ |
| `ORDERED` | สั่งแล้ว | รอของมาส่ง |
| `LOCAL_BUY` | ช่างซื้อเอง | ช่างไปซื้อแล้วอัปโหลดใบเสร็จ |
| `DONE` | เสร็จสิ้น | — |
| `PUR_REJECTED` / `CANCELLED` | ไม่อนุมัติ / ยกเลิก | — |

## 3. ติดตั้ง (ประมาณ 10 นาที)

### 3.1 สร้าง Google Sheet และโปรเจกต์ Apps Script

1. ไปที่ [sheets.new](https://sheets.new) สร้างไฟล์ใหม่ ตั้งชื่อ **Meiwa Tool Request**
2. เมนู **ส่วนขยาย (Extensions) → Apps Script** จะเปิดตัวแก้ไขโค้ดขึ้นมา
3. ตั้งชื่อโปรเจกต์ว่า `Meiwa Tool Request`
4. ใน **⚙️ Project Settings** ติ๊ก **Show "appsscript.json" manifest file in editor**
   และตั้ง Time zone เป็น **(GMT+07:00) Bangkok**

### 3.2 คัดลอกไฟล์ทั้งหมดจากโฟลเดอร์ `apps-script/`

ลบไฟล์ `Code.gs` เดิมที่มีอยู่ให้ว่าง แล้วสร้างไฟล์ตามตารางนี้ (ไอคอน **+** ข้างคำว่า Files)

| `Code` | Script (.gs) | `apps-script/Code.gs` |

| `Workflow` | Script | `apps-script/Workflow.gs` |

| `Notify` | Script | `apps-script/Notify.gs` |
| `Setup` | Script | `apps-script/Setup.gs` |
| `Api` | Script | `apps-script/Api.gs` |

| `ClientLib` | **HTML** | `apps-script/ClientLib.html` |

> ⚠️ **ชื่อไฟล์ต้องตรงตัวพิมพ์ใหญ่-เล็กเป๊ะ** เพราะโค้ดเรียกไฟล์ HTML ตามชื่อนี้
> (ไม่ต้องพิมพ์นามสกุล `.gs` / `.html` ตัวแก้ไขเติมให้เอง)

กด **💾 Save** แล้วกลับไปที่ Google Sheet **ปิดแล้วเปิดไฟล์ใหม่** จะเห็นเมนู **🔧 Meiwa Tool Request**

### 3.3 รันการติดตั้ง

ที่ Google Sheet เลือกเมนู **🔧 Meiwa Tool Request → 1) ติดตั้งระบบ (Setup sheets)**

ครั้งแรกจะมีหน้าต่างขออนุญาต:
**Review permissions → เลือกบัญชี → Advanced → Go to Meiwa Tool Request (unsafe) → Allow**
(ขึ้นคำว่า unsafe เพราะเป็นสคริปต์ที่เขียนเอง ยังไม่ผ่านการตรวจของ Google — ปกติ)

ระบบจะสร้าง 7 ชีต: `Config` `Technicians` `Requests` `Items` `Options` `History` `Notifications`
และสร้างโฟลเดอร์ Drive ชื่อ **Meiwa Tool Request - Files** สำหรับเก็บรูปและใบเสร็จ

## 4. Deploy เว็บแอป

ในตัวแก้ไข Apps Script: **Deploy → New deployment → ⚙️ → Web app**

| ช่อง | ค่าที่ต้องเลือก |
|---|---|
| Description | `v1` |
| **Execute as** | **Me (อีเมลของคุณ)** |
| **Who has access** | **Anyone** ← ต้องเป็นค่านี้ ช่างจึงเปิดได้โดยไม่ต้องล็อกอิน |

กด **Deploy** → คัดลอก **Web app URL** (ลงท้ายด้วย `/exec`)

ระบบจะบันทึก URL ลงชีต `Config → WEBAPP_URL` ให้เองเมื่อมีคนเปิดหน้าเว็บครั้งแรก
หรือจะวางเองเลยก็ได้ (ดูซ้ำได้จากเมนู **🔧 → 2) แสดงลิงก์เว็บแอป**)

**เปิดแจ้งเตือนสรุปงานค้างรายวัน (ไม่บังคับ):** เมนู **🔧 → 3) ติดตั้งแจ้งเตือนรายวัน**
ส่งอีเมลสรุปงานค้างให้ทีมจัดซื้อทุกเช้า ~08:00 น.

> 🔁 **แก้โค้ดแล้วต้อง deploy ใหม่ทุกครั้ง:**
> **Deploy → Manage deployments → ✏️ (แก้ไข) → Version: New version → Deploy**
> URL เดิมจะยังใช้ได้ ลิงก์ที่ส่งช่างไปแล้วไม่เสีย

## 5. ทดสอบ (ประมาณ 10 นาที)

เตรียม: มือถือ 1 เครื่อง (สวมบทช่าง) + คอมพิวเตอร์ 1 เครื่อง (สวมบทจัดซื้อ)
หรือใช้เบราว์เซอร์ปกติ + หน้าต่างไม่ระบุตัวตน (Incognito) ก็ได้

| # | ทำอะไร | ต้องเห็นอะไร |
|---|---|---|
| 1 | **[ช่าง]** เปิด `<WEBAPP_URL>` กรอกชื่อ + วันที่ต้องการใช้ → กด "เพิ่มเครื่องมืออีกรายการ" ให้ครบ 3 รายการ รายการแรกใส่ **สเปค + ยี่ห้อ/รุ่นที่อยากได้ + ราคาที่เห็นที่ร้าน + หมายเหตุ** และถ่ายรูปเครื่องมือตัวเดิม 1 รูป → **ส่งคำขอ** | ขึ้นเลขที่ `REQ-2026-0001` + ลิงก์ติดตาม + ปุ่มคัดลอกลิงก์ |
| 2 | ดูชีต `Requests` / `Items` | มี 1 แถว และ 3 แถว รหัสเป็น `REQ-2026-0001-01`, `-02`, `-03` และคอลัมน์ `brand_pref` `item_note` `required_date` มีค่าตามที่กรอก |
| 3 | เช็กอีเมลจัดซื้อ | ได้เมล "ใบขอซื้อใหม่ REQ-..." พร้อมสรุปทุกรายการและราคาที่ช่างเห็นที่ร้าน |
| 4 | **[จัดซื้อ]** เปิด `<WEBAPP_URL>?p=dash` ใส่ชื่อ + PIN | เห็นแท็บ "รอเสนอราคา 3" |
| 5 | กด **➕ เพิ่มตัวเลือก/เสนอราคา** ที่รายการแรก (ฟอร์มจะเตือนว่า "ช่างอยากได้ …") ใส่ **ยี่ห้อ** + **รุ่น** ผู้ขาย ราคา/หน่วย VAT 7 ค่าส่ง วันที่ได้ของ เงื่อนไขชำระ + แนบรูป → บันทึก | ย้ายไปแท็บ "รอช่างยืนยัน" |
| 6 | กด **📱 ข้อความ LINE** → คัดลอก | ได้ข้อความพร้อมลิงก์ ส่งให้ช่างทาง LINE ได้ทันที |
| 7 | **[ช่าง]** เปิดลิงก์ในมือถือ เลือกชื่อตัวเองในช่อง "ฉันคือ" | เห็นการ์ดแต่ละรายการ + รูปใหญ่ (แตะเพื่อซูม) + ราคารวม VAT + แถบเทียบกับราคาที่ร้าน |
| 8 | รายการ 1 กด **✅ ตรงสเปค ยืนยัน** | ขึ้นตารางเทียบ "จัดซื้อสั่งซื้อ vs ซื้อเองที่ร้าน" |
| 9 | กด **🚚 ให้จัดซื้อสั่งซื้อ** | สถานะเปลี่ยนเป็น **รอฝ่ายจัดซื้ออนุมัติ** (ยังไม่ใช่สั่งซื้อ) |
| 10 | รายการ 2 (เสนอราคาไว้ก่อน) กด **🔄 ขอแก้ไข** หรือ **❌ ไม่ตรงสเปค** ใส่เหตุผล → ส่ง | ย้ายไปแท็บ **"ช่างขอแก้ไข"** (นับแยกจาก "รอเสนอราคา") + จัดซื้อได้อีเมลพร้อมเหตุผล |
| 11 | รายการ 3 กด **🏪 ขอซื้อเองที่ร้าน** ใส่ราคาประเมิน + ร้าน + **ติ๊กยืนยันว่าขอใบกำกับภาษีได้** | ถ้าไม่ติ๊กจะกดส่งไม่ได้ ← ตรวจข้อนี้ด้วย |
| 12 | **[จัดซื้อ]** รีเฟรชแดชบอร์ด แท็บ "รออนุมัติ" | เห็นยอดรวม ผู้ตัดสินใจ เวลา และเตือนถ้ายอดเกิน `APPROVAL_LIMIT` |
| 13 | ใส่เลข PO แล้วกด **✅ อนุมัติสั่งซื้อ** ทั้งสองรายการ | รายการสั่งซื้อ → "รอสั่งซื้อ", รายการซื้อเอง → "ช่างซื้อเอง" |
| 14 | กด **📱 ข้อความ LINE** อีกครั้ง | ข้อความซื้อเองมี **ชื่อบริษัท เลขผู้เสียภาษี สาขา ที่อยู่** ครบสำหรับยื่นที่ร้าน |
| 15 | **[ช่าง]** รีเฟรชหน้าติดตาม รายการซื้อเอง → ใส่ราคาจริง + เลือกไฟล์ใบเสร็จ → **📤 ส่งใบเสร็จ** | สถานะเป็น "เสร็จสิ้น" + มีลิงก์ใบเสร็จ |
| 16 | **[จัดซื้อ]** รายการที่สั่งซื้อ กด "📦 บันทึกว่าสั่งซื้อแล้ว" → "✅ รับของแล้ว" | ทั้งใบจบครบ |
| 17 | กด **🕘 ประวัติ** ที่รายการใดก็ได้ | เห็นทุกขั้นตอน พร้อมชื่อคนและเวลา |

**ทางลัด:** เมนู **🔧 → สร้างข้อมูลทดสอบ (Demo data)** สร้างใบทดสอบ 2 รายการให้ทันที
พร้อมแสดงลิงก์สำหรับช่าง (ข้ามขั้นที่ 1 ไปได้)

**ทดสอบ logic บนเครื่องโดยไม่ต้อง deploy** (ถ้ามี Node.js 18+):

```bash
node tests/run.js          # workflow ฝั่งเซิร์ฟเวอร์ 77 เคส
node tests/client-test.js  # การ render ของทั้ง 3 หน้า 35 เคส
```

**ล้างข้อมูลทดสอบก่อนใช้งานจริง:** ลบแถวข้อมูล (ไม่ใช่หัวตาราง) ในชีต
`Requests` `Items` `Options` `History` `Notifications` แล้วรีเซ็ตเลขที่ใบด้วยการรัน
ฟังก์ชัน `PropertiesService.getDocumentProperties().deleteProperty('SEQ_REQ')` หรือปล่อยให้เลขเดินต่อก็ได้
(เลขที่ใบเริ่มนับ 0001 ใหม่เองทุกต้นปีอยู่แล้ว)

## 6. ใช้งานประจำวัน

**ช่าง** — ไม่มีอีเมลก็ใช้ได้ ไม่ต้องจำรหัส
1. เปิดลิงก์ฟอร์ม (ปักหมุดไว้ในแชท LINE กลุ่ม หรือทำ QR ติดที่บอร์ด)
2. ส่งคำขอ → คัดลอกลิงก์ติดตามส่งเข้าแชท LINE ของตัวเอง
3. ลิงก์หาย → เปิด `<WEBAPP_URL>?p=find` พิมพ์ชื่อตัวเองเพื่อดึงลิงก์กลับมา

**จัดซื้อ** — เปิด `?p=dash` วันละครั้ง ไล่ตามแท็บซ้ายไปขวา
`รอเสนอราคา → ช่างขอแก้ไข → รอช่างยืนยัน → รอเลือกวิธีซื้อ → รออนุมัติ → รอสั่งซื้อ → ช่างซื้อเอง`
หลังเพิ่มตัวเลือกหรืออนุมัติทุกครั้ง ให้กด **📱 ข้อความ LINE → คัดลอก** แล้ววางในแชทช่าง
(ระบบจะทำเครื่องหมายว่าส่งแล้วให้ ถ้ายังไม่ส่งจะมีแถบเตือนสีเหลืองค้างไว้)

ปุ่ม **💬 ส่งข้อความถึงช่าง** ใช้ตอนอยากบอกว่า "รุ่นนี้ที่ Global House ถูกกว่า
แนะนำให้ช่างซื้อเองแล้วเบิกคืน" ข้อความจะไปแสดงบนการ์ดของช่างโดยตรง

## 7. ข้อควรรู้และข้อจำกัด

**ความปลอดภัย** — ออกแบบให้ใช้ภายในองค์กร โดยแลกความสะดวกของช่างที่ไม่มีอีเมล
- ลิงก์ติดตามใช้ token สุ่ม 16 ตัวอักษร **ใครมีลิงก์ก็เปิดและกดยืนยันแทนได้**
  จึงบังคับให้เลือกชื่อผู้ตัดสินใจทุกครั้ง และบันทึกชื่อ+เวลาไว้เสมอ ไม่ควรส่งลิงก์ออกนอกบริษัท
- หน้าจัดซื้อป้องกันด้วย PIN ร่วม (เปลี่ยน `STAFF_PIN` ทันทีหลังติดตั้ง และเปลี่ยนเมื่อมีคนย้ายออก)
  เซสชันหมดอายุใน 6 ชั่วโมง
- ถ้าต้องการความเข้มงวดกว่านี้ ให้เปลี่ยน Who has access เป็น "Anyone within <องค์กร>"
  แต่ช่างจะต้องมีบัญชี Google ของบริษัท

**รูปภาพ** — เก็บใน Drive ของผู้ที่ deploy และตั้งเป็น "ผู้ที่มีลิงก์ดูได้" อัตโนมัติ
ถ้าองค์กรปิดการแชร์แบบลิงก์ รูปจะไม่ขึ้นสำหรับช่าง แก้โดยเปิดโฟลเดอร์
**Meiwa Tool Request - Files** แล้วตั้งการแชร์เป็น *Anyone with the link → Viewer* ด้วยมือ
รูปจะถูกย่อเหลือด้านยาวสุด 1,400 px ก่อนอัปโหลดเพื่อประหยัดเน็ตของช่าง

**อีเมลแจ้งเตือน** — ส่งจากบัญชีที่ deploy โควตา 100 ฉบับ/วัน (บัญชีฟรี) หรือ 1,500 ฉบับ/วัน (Workspace)

**LINE** — ค่าเริ่มต้นใช้วิธี "คัดลอกข้อความแล้ววางในแชท" ซึ่งใช้ได้ทันทีไม่ต้องตั้งค่าอะไร
ถ้าต้องการให้ส่งอัตโนมัติ ต้องสร้าง LINE Official Account + Messaging API channel
ใส่ token ในชีต `Config → LINE_CHANNEL_TOKEN` และใส่ userId ของช่างในคอลัมน์ `line_id`

**ขนาดที่รองรับ** — เหมาะกับหลักพันรายการต่อปี ถ้าชีต `Items` เกิน ~5,000 แถว
แดชบอร์ดจะเริ่มช้า ให้ย้ายข้อมูลปีเก่าออกไปไฟล์อื่น

**ยังไม่มีในเวอร์ชันนี้ (ตั้งใจตัดออกเพื่อให้เริ่มใช้ได้เร็ว)** — ออกเอกสาร PO/ใบขอซื้อเป็น PDF,
เชื่อมระบบบัญชี, งบประมาณรายแผนก, ผู้อนุมัติหลายระดับ, รายงานสรุปรายเดือน
